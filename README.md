# 作业小伙伴 Android 平板应用

这是一个面向小学生的单页作业执行应用。横屏平板显示“当前任务 + 待完成任务”双栏，窄屏时自动变为单列。

## 已实现

- 首次启动询问并本地保存孩子的名字
- 当日任务进度、当前任务和待完成任务
- 原地开始/暂停倒计时；倒计时结束后标记为超时
- 系统相机拍摄作业，确认后将任务标记为完成
- 适配横屏平板与窄屏设备的 Compose 布局

## 运行

用 Android Studio 打开该目录，并选择 Android API 35 的模拟器或实体平板运行即可。

## 跨周查看作业

顶部周历向右滑动查看下一周，向左滑动查看上一周，再点击日期查看当天作业。周历显示当前日期范围，并提供「回到今天」。作业和历史奖励随所选周加载，不再局限于本周；切周保留原来的星期选择。

## 打分结果

Trello 卡片描述第一行的「打分结果：良」保存最近一次批改评分：优、良、中、差，暂评显示为「打分结果：暂评·优」等，兼容 Trello 免费版。平板作业清单、当前作业和批改窗口显示带文字及图标的评分徽标，依次使用金色星标、绿色、橙色、红色样式；历史批改保留当次评分。没有评分时不显示徽标，提交订正后保留最近评分，复批才更新。

批改端使用新版 `cyeam trello card review --grade 良` 写回评分，需要时加 `--provisional`。CLI 只更新描述首行的评分字段，保留原题及其他说明；支持失败后用同一 review ID、同一评分和正文重试，不重复发布批改。

## 文本相机提交作业

选择「文本相机」拍照后，拖动四角框住完整作业页面，裁去桌面等页面外背景，并校正透视；支持旋转、裁切预览和重新框选。点「使用此页面」后加入待提交照片，每张照片都先确认页面，再统一上传到 Trello。页面里的题目、手写答案和配图保留，不依赖 OCR 或在线服务。

## 主屏幕护眼模式

主页始终使用柔和暖色背景、卡片和按钮，减少大面积亮白色，无需手动开启。此功能调整应用主页配色，不改变系统亮度或其他应用的显示设置。

## 小红花奖励

当天全部作业完成后立即获得小红花，超时完成也计入。截止时间继续用于显示超时和用时统计，不影响小红花。没有作业不发奖励；今天仍有未完成作业时等待，过去日期仍有明确未完成作业时保留原有黑色标记规则。

## 系统状态栏

学习模式保留平板系统状态栏中的时间、电量等系统信息。主页适配系统栏边距，避免内容被覆盖；显示样式由平板系统设置决定。

Device Owner 管理的平板在学习模式和普通模式下共用媒体音量规则：最低档位为最大音量的 30% 向下取整，且至少为 1 档。可正常调整到下限以上的任意音量；后台音量保护每秒检查，调到下限以下时恢复到最低允许档位。退出学习模式或临时开放不会停止音量保护，学习应用页的媒体音量按钮在两种模式下都立即生效。

## 学习应用管理

家长管理界面默认只显示「选择应用」入口，点击后弹出应用列表，可勾选学习时间允许打开的应用。选择立即保存并生效，点击「完成」关闭列表。

## 学习模式网站管控

Device Owner 模式下，Chrome 始终加入学习应用白名单。进入学习模式时向 Chrome 下发 `URLBlocklist = ["*"]` 和 `URLAllowlist = ["cyeam.com", "trello.com", "pgyer.com"]`（学习页、Trello 授权页、蒲公英更新下载页）；Chrome 的域名规则包含主域名及全部子域名（无需使用 `*.cyeam.com`）。页面静态资源不逐个加入导航白名单，跨站导航仍受限制。

`URLBlocklist`/`URLAllowlist` 是 Chrome 专有的托管配置，其他浏览器不识别。因此学习模式会通过可浏览 HTTPS 的应用查询识别所有已安装浏览器，把 Chrome 以外的浏览器一律挂起（即使曾被勾选），家长设置中这些浏览器的勾选框也被禁用。

进入学习模式前持久保存原有的两项网址策略，退出、定时结束或临时开放时恢复；其他 Chrome 托管配置保留。应用内 WebView 继续使用现有的 HTTPS Cyeam 域名检查。

设备验收：在 `chrome://policy` 确认两项策略状态和值，测试主域名、子域名、站外跳转及登录/音频流程；再测试临时开放、恢复学习、定时结束和学习期间重启。Chrome 策略实际生效需要在目标设备验证。

## Firebase

Android 应用 `com.homeworkbuddy` 已配置 Firebase 项目 `homework-70b75`，配置文件位于 `app/google-services.json`。Gradle 使用 Firebase BoM 管理 Analytics 和 Crashlytics 的 SDK 版本。

BoM 固定为 `34.0.0`，以兼容项目的 Kotlin `2.0.21`；升级 Firebase 时应同时检查 Kotlin 元数据兼容性。

- Analytics 自动采集启动、会话等基础事件，尚未添加作业内容或完成记录等业务事件。
- Crashlytics 自动收集崩溃；Gradle 插件为构建生成所需配置，启用代码混淆后支持上传映射文件。

设备验证需要联网。Analytics 可用以下命令开启 DebugView，验证完后关闭：

```bash
adb shell setprop debug.firebase.analytics.app com.homeworkbuddy
adb shell setprop debug.firebase.analytics.app .none.
```

Crashlytics 需要通过受控测试崩溃、重启应用后确认控制台收到报告。当前未增加会主动崩溃的入口。若控制台仍提示应用数据流创建失败，请在项目的 Google Analytics 集成中完成数据流设置；仅编译成功不能确认云端采集成功。

## Trello 同步

平板直接连接 Trello，家长授权后选择作业看板；授权 Token 使用 Android Keystore 加密保存，应用重启后继续使用。新授权请求为长期有效，不再按 30 天自动过期。已经签发的 30 天 Token 不会因为更新自动延长，失效后需要重新授权一次。

授权返回后，应用会用新 Token 检查原看板及列表是否仍可访问；验证通过就自动恢复连接，无需再次选择看板。原看板不可访问或列表发生变化时，再由家长选择。Token 被撤销、设备数据被清除或 Keystore 密钥失效时，仍需重新授权；网络故障不会清除原绑定。不要把 Trello Token 打包进 APK。

## 口算模式

每天创建一张作业卡片，在 Trello 描述中设置 `arithmetic`（或中文 `口算`），题目每行一道：

```text
类型: arithmetic
预计用时: 5
作业内容:
26 + 17 = ___
54 − 28 = ___
38 + 25 = ___
```

JSON 描述也支持 `{"type":"arithmetic","task":"26 + 17 = ___\n54 − 28 = ___"}`。题目保留原文，支持编号、空行和分号分隔；无需 PDF、附件或网页链接。

点击「开始做」后，题目直接显示在主页面左侧当前作业卡片里，计时缩为顶部文字；周历、头部状态和右侧作业清单沿用原界面。题目根据卡片实际宽高和系统字体大小自动调整列数、字号，优先完整显示；空间不足时支持上下滚动，长题换行，底部开始与提交按钮始终保留。作答和提交沿用现有流程，不自动批改。

## 普通作业链接

录入普通作业时可以直接把 HTTP/HTTPS 链接作为作业内容：

```text
类型: normal
作业内容: http://example.com/lesson
预计用时: 15
```

也支持描述中只填写一个链接，或将说明与链接分开填写：

```text
类型: 普通作业
作业内容: 完成第一课练习
作业链接: https://example.com/lesson
```

链接字段也可写成 `链接:` 或 `link:`；JSON 支持 `{"type":"normal","task":"完成第一课练习","link":"https://example.com/lesson"}`。

同步后显示「打开作业链接」，已完成的作业也能打开。网页在应用内展示，可返回和刷新，学习模式下无需修改 Chrome 白名单。家长录入的 HTTP/HTTPS 作业链接首次打开时不受域名白名单限制；网页后续点击和重定向按现有学习网站白名单管控（`cyeam.com`、`trello.com`、`pgyer.com` 及其子域名），被拦截时显示提示。跨站登录和短链接跳转也受此规则约束，建议直接填写最终作业网址。页面不提供地址栏或修改链接入口。Chrome 的学习模式网站管控保持原设置。不接受文件地址或应用跳转协议。为加载家长提供的 HTTP 网页，应用允许明文网络流量；原有学习应用页仍使用 HTTPS Cyeam 域名检查。

## PDF 附件作业

在 Trello 卡片描述中设置 `pdf_attachment` 标识，并将 PDF 文件直接上传到该卡片的附件中：

```text
类型: pdf_attachment
作业内容: 完成附件中的数学练习
预计用时: 20
```

也支持 JSON 描述：

```json
{"type":"pdf_attachment","task":"完成附件中的数学练习"}
```

中文类型别名为 `附件PDF`。沿用普通作业的学科标签和截止时间，无需在描述中填写 PDF 链接。附件按 `application/pdf` MIME 类型或 `.pdf` 文件名/URL 后缀识别。

平板同步后显示「预览 PDF」按钮；多个 PDF 分别显示按钮。预览在应用内打开，支持翻页、双指缩放、关闭和失败重试，已完成的作业也能查看。未上传 PDF 时显示提示。PDF 不会混入提交照片列表。

预览使用设备现有的 Trello 授权下载附件，临时文件在关闭后删除。单个文件最大 50 MB，不支持加密 PDF；请直接上传文件，不要添加第三方文件分享链接。

## 发布与自动升级

推送 `v*` 或 `x.y.z` 形式的 tag 会触发 `.github/workflows/android-release.yml`：CI 用 GitHub Secrets 里的 keystore 签名 release APK（版本号取自 tag，`versionCode` 取 workflow run number），同时发布到蒲公英和 GitHub Release。发布时会用 `git-chglog` 按版本号生成变更说明，并同时写入 GitHub Release 与蒲公英更新说明。App 启动时调用 `https://www.cyeam.com/api/apps/homework/update`，按 APK `versionCode` 检查更新；使用 DownloadManager 在非计费网络后台下载，重启后恢复任务。安装前校验大小、包名、versionCode 和签名，前台调起系统安装界面（首次需允许安装未知应用，最后仍需系统确认）。设置页保留手动检查、失败重试和安装入口；学习锁定模式下临时暂停 15 分钟以打开系统界面。蒲公英 API Key 仅保存在服务端，后端 `conf/app_updates.json` 的 homework 配置需部署后生效。

首次配置需要：

1. 生成发布 keystore：`keytool -genkeypair -v -keystore release.keystore -alias homeworkbuddy -keyalg RSA -keysize 2048 -validity 10000`（keystore 只保留在本地，不要提交）。
2. 在仓库 Settings → Secrets and variables → Actions 添加 `RELEASE_KEYSTORE_BASE64`（`base64 -i release.keystore` 的输出）、`HOMEWORK_RELEASE_STORE_PASSWORD`，以及蒲公英后台获取的 `PGYER_API_KEY`。
3. 每个发布构建都会等待蒲公英完成发布；成功后 Actions 日志和飞书通知会显示固定的蒲公英下载页链接。安装方式为公开安装、无有效期。
4. 平板上首次从 debug 签名切换到 release 签名时需卸载重装一次；之后同签名版本即可自动覆盖升级。

## 小李 Gateway 连接

家长在小李管理端点击“添加学习平板”生成一次性二维码，再在“家长设置 → 小李连接”中扫描。设备 token 使用 Android Keystore 的 AES-GCM 密钥加密后才会保存到本机。二维码内容是：

```json
{"pair_url":"https://xiaoli-server.example/xiaozhi/pair","code":"short-lived-one-time-code"}
```

应用向 `pair_url` 提交设备 ID、名称和 `device_kind=android`。在 Logto 会话所属的用户确认后，Gateway 应返回：

```json
{
  "device": {"id":"homework-tablet-abcd1234", "name":"小明的学习平板"},
  "websocket": {"url":"wss://xiaoli-server.example/xiaozhi/v1/", "token":"device-token"}
}
```

连接成功后，应用声明并实现以下 MCP 工具：

- `self.device.get_status`
- `self.homework.get_status`
- `self.homework.get_weekly_report`（查询本周作业完成周报）
- `self.notify.send`
- `self.audio_speaker.play_ogg_url`（流式播放服务端提供的 Ogg/Opus 音频）
- `self.audio_speaker.stop`（停止当前音频播放）
- `self.camera.take_photo`（先截取当前全屏，再在应用内单次拍照，将两张图一起交给小李视觉模型检查；拍照会显示提示并播放提示音，不打开系统相机）
- `self.camera.record_video`（前台调起系统相机录制小视频，默认最长 15 秒、上限 30 秒）
- `self.camera.start_stream` / `self.camera.stop_stream`（应用内共享学习画面；平板提示并播放提示音，1–3 fps；未充电默认及最长 5 分钟，充电或已充满时默认及最长 15 分钟，可随时手动停止；时长按启动时的充电状态确定）
- `self.kiosk.pause_15_minutes`（复用既有的临时开放 15 分钟逻辑）

屏幕截图需要 Android 11 及以上。在“家长设置 → 小李连接 → 配置屏幕截图权限”进入系统无障碍设置，手动开启“作业小伙伴屏幕截图”。服务只在收到 `self.camera.take_photo` 请求时截图，不读取无障碍节点或监听页面事件。截图保留当时桌面、微信等前台画面，不切换应用；长边最多 1600 像素，JPEG 单张不超过 2 MB。熄屏、未授权、超时或系统拒绝时继续提交相机照片，并在 MCP 返回中明确说明截图失败。系统安全保护的内容可能无法截取或被遮黑。

双图上传继续使用 `/mcp/vision/explain`：`image` 为 `photo.jpg`，可选 `screenshot` 为 `screenshot.jpg`，文本字段为 `question` 和可选的 `screenshot_error`。需要同步更新小李服务端的多图接收和视觉模型请求；`self.camera.snapshot` 保持原有单张上传协议。

这里的 MCP 是手写 JSON-RPC over WebSocket（小智风格 envelope），未使用官方 MCP SDK——因为服务端不是标准 MCP transport，官方 SDK 无内置 WebSocket transport。

## 本地头部状态

查看今天的页面时，日期栏右侧以窄卡片显示仰角、左右转角和相对距离三个指标，包括没有作业、未选中作业和全部完成的情况。作业页在前台且获得相机权限后，以约 3 次/秒运行 APK 内置的 ML Kit 人脸模型；画面仅在内存中处理，不保存、不上传。离开作业页、进入后台或拍照/共享画面时让出相机，返回后自动恢复。

- 俯仰角和左右转角：相对摄像头的角度，正俯仰角表示抬头，负值表示低头。
- 相对距离：最初 5 帧处于设定角度范围内的稳定观测自动建立并保存 1.00× 基准，大于 1 表示更远。这是同一人相对平板的粗略距离比例，不是厘米，也不是头到书本的距离。
- 多人、无人、眼部遮挡或俯仰/转头角超过 35° 时，不显示距离估计；人脸丢失或检测重启后沿用已保存的基准；不同相机分辨率和方向分别保存。移动平板或换人后，在家长设置中重新校准。

实机验收：首次权限允许/拒绝、抬头低头、左右转头、前后移动、无人/多人、横竖屏切换、后台返回，以及检测期间远程拍照/共享后恢复。确认模型在断网状态下仍有输出。

### 头部姿势提醒

家长设置 → 头部姿势提醒可保存三个指标的上下限、触发/恢复秒数和提示音选项，也可恢复默认范围或重新校准距离。默认俯仰 −29°～−9°、左右转角 −23°～7°、距离 0.85×～1.20×；这些是本次实测姿势的试用范围，不是医学标准。

同一项连续超限 3 秒后，指标栏变色并显示调整提示；正常持续 2 秒后解除。超限后按原因播放内置中文语音（媒体音量）：头太高、头太低、转回来看作业、离平板太近或太远。多个问题轮流播报，每句结束后间隔 8 秒。提醒解除、检测暂停、离开页面或关闭语音提醒时立即停止。语音由 `scripts/generate-pose-voice.py` 生成并随 APK 打包，播放不依赖网络或平板的 TTS 引擎。无人、多人、画面过期或相机暂停时清除提醒计时；无法估算距离时仅暂停距离提醒。

当前提醒策略：仅保留俯仰角低于下限的“头过低”提醒。抬头、左右转头和距离变化继续显示数值及保留参考设置，但不触发变色或语音，不作为不专注的判断依据。

### 坐姿提醒记录

家长管理界面的「坐姿提醒记录」卡片显示今日提醒次数和最低俯仰角；点击「查看历史记录」可按日期查看每日汇总，以及每次提醒的时间、最低俯仰角和当时的提醒阈值。

同一次持续低头只计一次，重复语音不重复计数；关闭语音时仍记录屏幕提醒。恢复正常后再次触发，或检测中断后重新触发，另计一次。跨午夜的一次提醒归入首次触发日期。每日最低角度来自当天所有有效检测，即使未触发提醒也会记录；每次提醒的最低角度还包含触发前的连续低头样本。

角度是相对摄像头的俯仰角，数值越负表示头越低（例如 −40° 比 −30° 更低），不是离桌面的高度。数字记录仅保存在本机，重启后仍可查看，不保存或上传检测画面。记录从安装此版本开始累积，无法补录此前的提醒。

## 查看批改

主页统一使用同一个作业列表。刷新后，有批改结果的作业显示「查看批改结果」，在大弹窗中展示，可放大文字、放大图片或播放批改语音；点击「开始改错」也会打开弹窗，待改错时底部固定显示「提交改错」按钮；每条结果只包含一种内容。待改错作业还显示「提交修改后的内容」，可直接拍照、录音或输入文字重新提交。历史作业通过周历选择日期查看。提交端需在原 Trello 卡片发布带标记的评论，图片和语音先上传原生附件。完整字段、示例与重试约定见 [批改结果提交协议](docs/homework-review-protocol.md)。


批改有错时，提交端将原卡片移入「待改错」并清除完成标记；APP 会将历史日期的待改错任务一并显示在当前任务里。孩子通过「提交修改后的内容」上传后，卡片进入「已改错」，播放专门的鼓励小曲；待下一次批改确认是否改对。首次提交的鼓励小曲继续保留。详见提交协议的“有错、订正与鼓励流程”。

作业提交状态统一为「待完成 → 已完成 → 待改错 → 已改错」。已改错表示订正已提交，计入完成进度；复批通过保留已改错，仍有错误则再次进入待改错。状态和批改按钮沿用原作业列表；批改结果在大弹窗中阅读，关闭后回到原作业，提交改错沿用原提交流程。
