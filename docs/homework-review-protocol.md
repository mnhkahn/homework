# 批改结果提交协议 v1

平板入口：主页「查看批改」→ 选择作业。读取绑定看板的「待完成」「已完成」「待改错」三列中未归档卡片，包含历史日期和没有截止日期的卡片；按作业查看最新和历史批改。进入模式、点击「刷新批改」或每隔约一分钟重新获取。此页面仅展示，提交端另行开发。

## 存储位置与唯一识别标记

始终写入**原作业卡片**，不另建卡；带评分时只在描述第一行写入或更新「打分结果」，保留原题及其他说明。批改完成后按下方状态约定更新列表和 dueComplete。每次批改用一条 Trello 评论作为发布记录，评论必须以 `作业批改：`（全角冒号）开头，后接一个 JSON 对象；不加 Markdown 代码围栏。其他评论，包括孩子的 `作业文字提交：`，不算批改。

每条评论只能包含三种类型之一：`text`、`image`、`audio`。不支持一条结果混合图片、文字和语音。平板按 Trello 评论时间倒序显示，首条标为“最新批改”，其余保留为历史。没有有效评论显示“还没有批改结果”；畸形 JSON、未知版本/类型、空内容和混合内容不作为有效批改。

## 文字

向 `POST /1/cards/{cardId}/actions/comments` 提交 `text` 参数，其值为以下完整字符串：

```text
作业批改：
{"version":1,"type":"text","text":"第3题需要订正：注意进位。\n其余题目正确。"}
```

`text` 必须是非空字符串，不能同时有 `attachment_id`。用 JSON 序列化器处理正文换行、引号等转义，不手拼 JSON。正文按纯文本显示。

## 图片

1. 把**一张图片文件**上传到原卡片：`POST /1/cards/{cardId}/attachments`，multipart 字段为 `file`、`name`。
2. `name` 使用 `homework-review-image-{reviewId}.jpg`（或 `.png` / `.webp` / `.gif` / `.jpeg`）；上传正确 MIME。该前缀保留给批改，平板会从原始作业照片列表中排除它。
3. 从上传响应取附件 `id`，写入同一卡片的发布评论：

```text
作业批改：
{"version":1,"type":"image","attachment_id":"实际的Trello附件ID"}
```

不要放附件 URL、外链、Base64 或 Markdown 图片，不传 `text`。平板从同一卡片附件表中按 ID 解析图片，使用设备 Trello 授权读取并支持放大。

## 语音

与图片相同，先上传**一段音频文件**再发布评论。附件 `name` 使用 `homework-review-audio-{reviewId}.m4a`。建议 `audio/mp4` 的 M4A/AAC 或 `audio/mpeg` 的 MP3；其他支持识别的扩展名有 wav、aac、ogg、opus、amr、3gp，实际解码能力依设备而定。

```text
作业批改：
{"version":1,"type":"audio","attachment_id":"实际的Trello附件ID"}
```

不传 `text`。平板鉴权下载后在 APP 内播放、暂停，离开详情或退到后台停止播放；临时文件离开组件后清理。音频下载上限 50 MiB，建议保持录音短小。Token 不传给外部播放器或存储重定向地址。

## 发布顺序、重试和更新

- `reviewId` 由提交端生成（推荐 UUID），同一次提交重试复用；附件上传成功后，才发布评论。只有附件、没有发布评论时，平板不会显示它。
- 评论的 Trello action ID 是平板的记录 ID；重复 POST 评论会产生重复历史。提交端需保存上传的附件 ID 与发布成功的 action ID，超时后查询卡片评论/附件确认是否已成功，避免盲目重发。Trello 没有此协议的原生幂等键。
- 新一轮批改新建评论并保留旧评论。修正文案可通过 Trello 的评论编辑接口更新原 action；平板按原评论时间排序。需要成为最新版本时新建评论。
- 不删除仍被历史评论引用的附件。附件丢失或类型不匹配时，APP 显示错误提示，支持刷新重试。
- 上传必须是卡片原生文件附件（`isUpload=true`），不接受第三方链接附件。Trello 授权沿用提交端自己的配置，本文及 APP 不向提交端提供设备 token。

## 最小验收

在测试卡分别发布一条 text/image/audio 评论，确认三类结果均能展示、最新在前；孩子原始照片/录音和普通评论不会成为批改。再检查无评论、已删除附件、网络中断、切换作业和离开页面后的播放停止。该功能不自动执行批改或评分。


## 有错、订正与鼓励流程

状态来源是 Trello 卡片所在列表，批改正文中的“错”字或历史批改不会自动触发状态变化。提交端新增 `has_errors` 布尔字段（适用于 text/image/audio 三类内容），并负责发布批改后更新卡片状态：

| 操作 | 原卡片所在列表 | dueComplete | 平板行为 |
| --- | --- | --- | --- |
| 孩子首次提交成功 | 已完成 | true | 播放现有提交鼓励小曲 |
| 批改发现有错，`has_errors: true` | 待改错 | false | 显示“待改错”“开始改错”“提交修改后的内容” |
| 孩子提交订正成功 | 已改错 | true | 播放专门的订正鼓励小曲，等待下一轮批改 |
| 再次批改仍有错 | 待改错 | false | 再次进入改错流程 |
| 批改通过，`has_errors: false` | 初次提交为已完成，订正提交保留已改错 | true | 展示本次批改通过 |

提交端发现有错的完整步骤：

1. 按当前看板查询列表 ID，查找精确名称“待改错”；缺少则创建，不能把列表名直接当作 ID。新绑定的平板也会自动创建该列表；已经绑定的平板会发现新列表，无须重新授权。
2. 如需图片/音频，先上传原生附件，再发布评论。示例：

```text
作业批改：
{"version":1,"type":"text","text":"第3题需要订正，请检查进位。","has_errors":true}
```

3. 调用 `PUT /1/cards/{cardId}`，在同一次请求提交 `idList=<待改错列表ID>`、`dueComplete=false`。只有明确完成判读后才设置此状态；不从图片、语音或正文关键词猜测有错。
4. 判定通过时，评论写 `has_errors:false`，初次提交保留「已完成」，订正复批保留「已改错」，设置 `dueComplete=true`。

旧版不带 `has_errors` 的评论仍可展示，但不表达是否通过。只发布 `has_errors:true` 而不移动列表，不算完成“待改错”发布；外部提交端遇到移动失败应显示发布未完成并重试，不能报告全部成功。

平板把所有日期的“待改错”任务加入当前任务列表，避免昨天或更早的作业被当天筛选隐藏。订正沿用照片、录音、文字提交；附件仍属于原卡片，文字评论前缀为 `作业订正文字提交：`，附件订正追加 `作业订正提交：<提交ID>`。订正提交后进入“已改错”表示订正已提交，**不代表已经改对**；历史带 `has_errors:true` 的评论不会把它重新退回待改错。下一轮判读需要基于最新订正材料重新发布批改和列表状态。

只在提交成功后播放小曲；网络失败保留原状态和待重试记录，联网补交成功后再鼓励。自动刷新、浏览历史批改不会触发鼓励音效。


## 订正后重新提交的入口

“待改错”的原作业会重新开放提交，不会被先前“已完成”或本地完成记录锁住。孩子可以在统一的作业列表或当前任务点击「提交修改后的内容」，直接重新选择拍照、录音或文字。刷新后，有协议有效批改评论的作业显示「查看批改结果」按钮，打开大弹窗专门展示批改结果，支持放大、缩小文字；点击「开始改错」也会打开弹窗。底部固定显示「提交改错」按钮（仅待改错状态），沿用已有提交方式。历史作业沿用周历日期选择，不再设置独立的批改作业列表。

从作业列表打开订正入口时，APP 会重新校验卡片仍在“待改错”列表，避免用旧批改状态重复打开已提交的任务。历史日期的作业同样可直接提交。每次新的照片/录音提交生成新的提交 ID，继续向**同一 cardId 的附件集合**追加文件；文字追加到**同一 cardId 的评论**。原始提交和历次订正材料都保留，不覆盖、不新建卡片。成功后进入“已改错”，再被批改退回“待改错”时入口再次开放，可反复订正。


CLI 发布时使用 `cyeam trello card review <card-id> --text <批改正文> --has-errors=true|false`（图片和语音同样支持）。省略该参数只发布内容，不改变状态。评论写入成功但状态更新失败时，用同一 review ID 和相同参数重试，只补状态；已完成的同一 review ID 不重放后续流转。


## 打分结果（兼容免费版）

卡片描述第一行为 `打分结果：100`、`打分结果：优`、`打分结果：良`、`打分结果：中` 或 `打分结果：差`；暂评为 `打分结果：暂评·良`。批改端传 `--grade 良`，暂评另加 `--provisional`。满分传 `--grade 100`，表示整份全对、自动按 `has_errors: false` 批改通过；不可与 `--provisional` 或 `--has-errors=true` 并用。只替换首行已有的同名字段（兼容半角冒号），否则在原描述前新增一行，不改题目和原有换行。

批改评论增加可选字段 `grade`（100/优/良/中/差）和 `provisional`（布尔，默认 false），与 text/image/audio 三种内容兼容，例如：

```text
作业批改：
{"version":1,"type":"text","text":"第3题请检查进位。","grade":"良","has_errors":true}
```

描述保存最近评分，评论保存当次评分。平板在清单、当前作业和批改窗口用奖杯（100）、金色星标（优）、绿色（良）、橙色（中）、红色（差）展示，并同时显示文字；未评级不显示徽标。100 分隐藏改错入口，其余等级仍由 `has_errors` 决定是否改错。订正提交仍显示最近评分，等待复批更新。

先发布评论，再更新评分，最后按需更新列表状态，各步骤独立保存成功检查点。描述更新失败用同一 UUID、相同正文及评分参数重试，只补未完成步骤；已完成的 UUID 不重放旧评分。不要同时编辑同一卡片描述。旧评论没有评分字段仍可展示。
